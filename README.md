# Статистика Telegram-канала → дашборд на GitHub Pages

Каждый день GitHub сам запускает скрипт. Скрипт забирает из канала по каждому посту просмотры, реакции, пересылы и комментарии, а также число подписчиков, и сохраняет всё в `docs/data.json`. Дашборд `docs/index.html` читает этот файл и открывается по ссылке вида `https://<логин>.github.io/<репозиторий>/`.

Ни сервер, ни Google, ни включённый компьютер не нужны.

## Что на дашборде

- **Плитки:** подписчики и их прирост за период, число постов, суммарные просмотры, средний охват поста, вовлечённость.
- **График подписчиков** по дням.
- **Просмотры по постам.** При наведении на столбик видно сам пост, при клике — график того, как росли его просмотры.
- **Таблица всех постов** с сортировкой по любой колонке. Реакции разбиты по эмодзи, в колонке `utm_content` — метка из ссылки в посте.
- **Переключатель периода:** 7 / 30 / 90 дней / всё время. Есть тёмная тема, страница нормально выглядит с телефона.

Альбом из нескольких фото считается одним постом. Служебные сообщения (закрепы и т.п.) пропускаются. Каждый день обновляются посты за последние 60 дней. Более старые посты остаются на дашборде с последними собранными цифрами.

## Настройка (один раз, ~20 минут)

### 1. Ключи Telegram

1. Откройте [my.telegram.org](https://my.telegram.org) и войдите по номеру телефона администратора канала.
2. Откройте **API development tools** и заполните форму. Название любое, платформа любая.
3. Сохраните **api_id** (число) и **api_hash** (длинная строка).

### 2. Строка сессии (на своём компьютере, один раз)

```bash
pip install -r requirements.txt
python login.py
```

Скрипт спросит api_id, api_hash, телефон, код из Telegram и облачный пароль, если он включён. В конце он напечатает длинную строку. Это и есть **TG_SESSION**.

> ⚠️ **Строка сессии даёт полный доступ к аккаунту.** Не пересылайте её никому, а храните только в GitHub Secrets.
> В Telegram она будет видна в «Настройки → Устройства». Если её там завершить, повторите `login.py`.

Проверить, что всё работает, можно прямо на компьютере:

```bash
export TG_API_ID=... TG_API_HASH=... TG_SESSION=... TG_CHANNEL=@канал
python collect.py
python -m http.server -d docs 8000   # и откройте http://localhost:8000
```

### 3. GitHub

1. Создайте репозиторий и загрузите в него эти файлы.
2. Откройте **Settings → Secrets and variables → Actions → New repository secret** и добавьте четыре секрета:
   `TG_API_ID`, `TG_API_HASH`, `TG_SESSION`, `TG_CHANNEL` (например `@mts_belarus`).
3. Откройте **Actions → Telegram stats → Run workflow**. Это первый запуск вручную. В репозитории появится `docs/data.json`.
4. Откройте **Settings → Pages → Source: Deploy from a branch → Branch: `main`, папка `/docs`** и нажмите **Save**. Через минуту-две дашборд откроется по ссылке, которую покажет эта страница.

Дальше всё работает само: каждый день около 06:30 по Минску данные обновляются, и страница показывает свежие цифры.

### Нюансы

- **На бесплатном тарифе GitHub Pages работает только для публичного репозитория, и сайт открыт всем, у кого есть ссылка.** Секреты при этом не видны никому. Видны код и `data.json`, а в нём только то, что у публичного канала и так видно любому: просмотры, реакции, подписчики. Если на дашборд попадут внутренние данные (корзины, продажи), Pages не подойдёт. Это вопрос к политике компании.
- **Первый запуск** обновит только последние 60 дней. Чтобы подтянуть историю постов за год, добавьте во вкладке **Variables** переменную `DAYS_BACK = 365`, запустите workflow, а потом удалите переменную.
- **История роста просмотров** копится с первого запуска. Задним числом Telegram её не отдаёт.
- **Время в расписании указано в UTC.** GitHub может запустить задачу с опозданием на 5–30 минут, и это нормально.
- **Telegram иногда разлогинивает сессии, которые заходят с серверов GitHub.** Если в логах Actions появится «Сессия недействительна», повторите шаг 2. Если это повторяется часто, заведите отдельный аккаунт, сделайте его админом канала и логиньтесь им.

## Переходы на сайт и корзины (пока не сделано)

Telegram не знает, кто кликнул по ссылке. Эти данные есть только в аналитике сайта.

1. **В каждом посте ставьте ссылку с UTM-метками.** Метка `utm_content` для каждого поста должна быть своя:
   `https://site.by/tariff?utm_source=telegram&utm_medium=post&utm_content=super_14oct`
   Скрипт уже находит `utm_content` в ссылках и кнопках поста и показывает его в таблице.
2. **Дальше нужен доступ к аналитике сайта** (Яндекс Метрика или Google Analytics), чтобы по этим меткам забирать визиты и цель «корзина». Это отдельный кусок работы, и для него нужен API-доступ от владельцев сайта.
